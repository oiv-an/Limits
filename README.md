# Limits

Остаток лимитов подписок **Claude** и **Codex (ChatGPT)** прямо в строке меню macOS. Поддерживает несколько аккаунтов каждого вида.

Нативное приложение на Swift / SwiftUI / AppKit для macOS 14+. Работает в строке меню без значка в Dock. Не требует API-ключей и не создаёт запросов к моделям — только читает лимиты подписки.

## Возможности

- **Несколько аккаунтов:** любое число подписок Claude и Codex одновременно. Аккаунт называется по email, название можно изменить.
- **Строка меню:** все аккаунты подряд — значок сервиса, остаток в процентах и время до сброса. Если аккаунтов одного сервиса несколько, под значком виден номер аккаунта.
- **Claude:** два значения через слэш, например `9/42%` — 5 часов / неделя; время до сброса в том же порядке. Модельные лимиты (Sonnet, Opus и др.) — в окне по кнопке «Ещё лимиты».
- **Codex:** наименьший остаток выбранного лимита и время его сброса.
- **Плавающая панель** поверх окон (кнопка булавки): перетаскивается, положение сохраняется.
- **Автообновление** раз в 2, 5 или 10 минут, обновление после выхода из сна, автозапуск при входе в Mac.
- **Зашифрованное хранение:** все входы — в одном файле, ключ создаётся на вашем Mac и доступен только Limits.

## Установка

1. Скачайте `Limits-1.3.0-universal.dmg` из [последнего релиза](https://github.com/oiv-an/Limits/releases/latest).
2. Откройте образ и перетащите `Limits.app` в `Applications`.
3. Запустите Limits из папки «Программы».

Сборка универсальная — работает на Apple Silicon и Intel.

### Первый запуск: «приложение не проверено»

Релиз собран без сертификата Apple Developer ID (подписан локально, ad-hoc) и не проходил нотариальную проверку Apple, поэтому macOS при первом запуске его заблокирует. Это нормально для бесплатных open-source приложений. Варианты:

- **Системные настройки → Конфиденциальность и безопасность** → внизу «Limits заблокировано…» → **«Всё равно открыть»** → подтвердите паролем.
- Или в Терминале, один раз после установки:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Limits.app
  ```

Не доверяете готовой сборке — [соберите сами](#сборка-из-исходников), это пара минут.

### Запрос связки ключей

Limits хранит ключ шифрования в вашей связке ключей. У сборки без Developer ID подпись меняется с каждой версией, поэтому **после установки новой версии** macOS один раз спросит, разрешить ли Limits доступ к ключу «pro.ivol.Limits.vault». Введите пароль Mac и нажмите **«Всегда разрешать»** — до следующего обновления запросов не будет. Если нажать «Отклонить», аккаунты не пропадут: Limits покажет предупреждение и повторит попытку при следующем обновлении.

## Как пользоваться

Откройте окно кликом по индикатору в строке меню.

- **Добавить аккаунт:** кнопка «+» → «Аккаунт Claude…» или «Аккаунт Codex…». Вход проходит в обычном браузере.
- **Второй аккаунт того же сервиса:** перед добавлением выйдите из claude.ai / chatgpt.com в браузере (или используйте другой профиль браузера), иначе браузер подставит уже вошедший аккаунт.
- **Меню «…» на карточке:** обновить, переименовать, войти заново, удалить аккаунт.
- **Настройки** (кнопка внизу окна): частота обновления, лимит Codex для строки меню, автозапуск, плавающая панель.
- Точка после процента — показаны сохранённые данные (идёт обновление или была ошибка). «—» — данных нет. После времени сброса приложение ждёт подтверждённые свежие данные и не показывает 100% заранее.

## Подключение аккаунтов

### Claude

Вход через браузер (Google, Apple или email) по OAuth с PKCE и проверкой `state`; обратный переход принимается только на `127.0.0.1`. Используется подписка Claude, а не отдельный API-биллинг. Сессия продлевается автоматически и сохраняется после сна и перезапуска. Если Claude отозвал вход, приложение предложит подключиться заново; браузер само не открывает.

Запросы лимитов идут только на `api.anthropic.com`, продление входа — на `platform.claude.com`. Это внутренние сервисные методы, а не публичный стабильный API: при изменениях на стороне Claude может понадобиться обновление. При ответе 429 запросы приостанавливаются минимум на 5 минут с учётом `Retry-After`.

### Codex

Нужен установленный [Codex](https://openai.com/codex/) (приложение или CLI `codex`) — Limits использует его программу для входа и чтения лимитов.

- Вход вашего Codex из `~/.codex` **не читается и не меняется**: само приложение Codex продолжает работать как раньше.
- Каждый аккаунт подключается в Limits отдельно: `codex login` запускается во временной папке `CODEX_HOME`, полученный `auth.json` сразу переносится в зашифрованное хранилище, папка удаляется.
- При обновлении вход на несколько секунд записывается во временную папку (права `700` / `600`), запускается короткоживущий Codex App Server с методами `initialize` и `account/rateLimits/read`, обновлённые токены возвращаются в хранилище, папка удаляется.
- Задачи и запросы к модели не создаются.

## Хранение данных и безопасность

- Все аккаунты — входы Claude и Codex, названия и последние показания лимитов — в одном файле `~/Library/Application Support/pro.ivol.Limits/accounts.vault` (права `600`, каталог `700`, атомарная запись).
- Файл зашифрован **AES-256-GCM**. Ключ — случайные 256 бит, которые Limits создаёт сам при первом запуске и сохраняет в связке ключей входа этого Mac (`pro.ivol.Limits.vault`, без синхронизации с iCloud).
- Доступ к ключу разрешён только приложению Limits (по его подписи кода). Другие программы прочитать файл не могут, а копия файла на другом Mac бесполезна: там Limits создаст новый ключ и попросит подключить аккаунты заново.
- Пароли пользователя, Touch ID и Secure Enclave не используются.
- Настройки интерфейса — стандартные preferences `pro.ivol.Limits`.
- Нет аналитики, телеметрии, серверной части и внешних зависимостей. Коды и адреса авторизации не журналируются.

Обновление с версии 1.2: сохранённый вход Claude автоматически переносится в зашифрованное хранилище, старые открытые файлы (`claude-session.json`, `usage-cache.json`) удаляются. Аккаунт Codex нужно подключить заново через «+».

**Удалить всё:** удалите аккаунты в приложении (или папку `~/Library/Application Support/pro.ivol.Limits`) и запись `pro.ivol.Limits.vault` в «Связке ключей».

## Сборка из исходников

Нужны Xcode или Command Line Tools со Swift 6.0+.

```sh
git clone https://github.com/oiv-an/Limits.git
cd Limits
./scripts/build.sh
open dist/Limits.app
```

Готовое универсальное приложение (`arm64` + `x86_64`) — `dist/Limits.app`. Собранное у себя приложение macOS не блокирует.

Подпись:

- Если в связке ключей есть сертификат «Developer ID Application», сборка подписывается им автоматически — тогда доступ к ключу хранилища сохраняется между версиями без запросов.
- Другой сертификат — через `LIMITS_CODESIGN_IDENTITY="…"`.
- `LIMITS_CODESIGN_IDENTITY="-"` — принудительно ad-hoc (так собираются публичные релизы).

Тесты:

```sh
swift test --disable-sandbox
```

Установочный образ и контрольная сумма (`release/`):

```sh
./scripts/package-release.sh
```

Если задан профиль `LIMITS_NOTARY_PROFILE` и сертификат Developer ID, образ дополнительно отправляется на нотариальную проверку Apple.

Проверка подключений и рендер интерфейса в PNG (без захвата экрана):

```sh
./dist/Limits.app/Contents/MacOS/Limits --smoke-test "$PWD/verification"
```

`verification/smoke-result.json` содержит результат по каждому аккаунту.
